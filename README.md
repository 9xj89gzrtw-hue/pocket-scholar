# Pocket Scholar

Offline research assistant for Android. A local LLM, a local encyclopedia, no network.

The app has **no INTERNET permission in its manifest** — it cannot make a network call even
in principle. Everything it knows ships with it: a quantized model on disk and a bundled
BM25 index over 6,418 encyclopedia articles.

## Why

Phones travel into airplanes, tunnels, mountains and disasters. Remote inference stops
working exactly when a lookup is most useful, and a 1B model on its own hallucinates on
anything specific. Pocket Scholar pairs a small local model with a real retrieval index, so
answers are grounded in text that is present on the device and cited by title.

## Architecture

```
question ──► BM25 over bundled articles ──► top-4 passages
                                              │
                    ChatML prompt with passages and citation rules
                                              │
                              llama.cpp (bundled binary, CPU)
                                              │
                        answer with [1] [2] citations + source list
```

* **Inference** — `llama-completion` from llama.cpp, cross-compiled for `arm64-v8a` and
  `x86_64` with the Android NDK and shipped as `libllama-completion.so` so the loader
  extracts it with execute permission. No JNI layer to rot, no daemon, no chat UI: one
  process per question, prompt in, text out.
* **Retrieval** — BM25 (k1 = 1.2, b = 0.75) built in memory at first launch over
  `app/src/main/assets/knowledge/pack.jsonl` (6,418 article summaries, 7.9 MB).
* **Model** — any GGUF chat model. The recorded demo uses Qwen2.5-1.5B-Instruct Q4_K_M (~1.0 GB);
  0.5B is the fast floor, 3B still fits comfortably inside the 12 GB budget.

## Build

```bash
# 1. cross-compile llama.cpp
export NDK=$ANDROID_NDK_LATEST_HOME
git clone --depth 1 --branch v0.7.0 https://github.com/ggml-org/llama.cpp
cmake -S llama.cpp -B llama.cpp/build-android \
  -DCMAKE_TOOLCHAIN_FILE=$NDK/build/cmake/android.toolchain.cmake \
  -DANDROID_ABI=arm64-v8a -DANDROID_PLATFORM=android-26 -DANDROID_STL=c++_static \
  -DBUILD_SHARED_LIBS=OFF -DLLAMA_CURL=OFF -DGGML_OPENMP=OFF -DCMAKE_BUILD_TYPE=Release
cmake --build llama.cpp/build-android --target llama-completion -j
mkdir -p app/src/main/jniLibs/arm64-v8a
cp llama.cpp/build-android/bin/llama-completion \
   app/src/main/jniLibs/arm64-v8a/libllama-completion.so

# 2. build the APK
./gradlew assembleDebug

# 3. install and give it a model
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb push Qwen2.5-1.5B-Instruct-Q4_K_M.gguf \
  /sdcard/Android/data/org.pocketscholar/files/model.gguf
```

Or skip step 3's push: copy any `.gguf` to the phone and use the **Model…** button in the
app. Models are never downloaded by the app.

### Model options

| model | size | notes |
|---|---|---|
| Qwen2.5-0.5B-Instruct Q4_K_M | 0.4 GB | fastest, weakest answers |
| Qwen2.5-1.5B-Instruct Q4_K_M | 1.0 GB | the recorded demo |
| Qwen2.5-3B-Instruct Q4_K_M | 1.9 GB | best quality that stays interactive on CPU |

## Knowledge pack

`app/src/main/assets/knowledge/pack.jsonl` is generated by
`scripts/build_knowledge_pack.py` from Wikipedia's own curriculum: the
[Vital Articles](https://en.wikipedia.org/wiki/Wikipedia:Vital_articles) Level 3 and Level 4
lists (10,018 titles across science, history, geography, technology, philosophy). The
shipped pack holds the 6,418 of them that have a usable intro extract; `scripts/fill_knowledge_pack.py`
appends whatever a rate-limited first pass missed. Both scripts write one JSON object per line.
The loader accepts any JSONL with `title` + `extract`, so a bigger pack (a full dump slice,
a domain corpus) is a drop-in replacement.

## What it is and is not

It is a real offline retrieval-augmented reader: answers built from passages that are on the
device, a source list under every answer, no network, no Play Services, works on GrapheneOS.
The model is asked to name the passage behind each point (`[1]`, `[2]`); a 1.5B model does
that most of the time, not always, so the app also prints the sources it actually retrieved —
that list, not the model's good manners, is what you can check.

It is not a frontier model. A 3B model with 200 million facts missing will lose to the
internet on long-tail questions; the honest claim is that it is dramatically better than a
bare 1B model of the same size, because the answer has to come from a retrieved passage
where one exists, and it says so when none does.

## Verification

* `AndroidManifest.xml` contains no `INTERNET` permission.
* `adb shell dumpsys package org.pocketscholar | grep -i permission` is empty.
* The CI workflow builds the APK, installs it on a fresh emulator, asserts the missing
  INTERNET permission, pushes a model, asks three questions and records the screen — the
  artifacts are the demo. `logcat.txt` from the same run shows the binary, the ABI, the
  model size and the measured characters per second.
* The arm64-v8a `libllama-completion.so` from the released APK was also executed on an
  `arm64-v8a` Android 13 emulator, i.e. the same binary a phone runs.

## Demo

The three recorded runs — the Bronze Age collapse (explanation), photosynthesis vs cellular
respiration (comparison) and the fall of Rome (reasoning) — plus screenshots, are in the
`v0.1.0` release. They were produced by `.github/workflows/android.yml` on a fresh API-33
emulator: install, push the model, ask a question, record the screen, stop the recording,
pull it. Nothing is pre-baked — regenerating the demo means re-running the workflow.
